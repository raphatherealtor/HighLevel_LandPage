## Product

- Preliminary results provide value before capture.
- Deliverable and follow-up expectations are explicit.
- Unsupported properties never receive fabricated values.
- Low confidence is visible.
- The public result uses only facts a consumer could obtain publicly.
- Private-input controls remain unavailable until the visitor affirms personal ownership.
- Declining ownership attestation leaves the public experience usable and stores no non-public property facts.
- Every displayed and transmitted input is labeled public source, user-provided, or calculated.

## Calculation

- Every formula has unit tests and manually reviewed golden examples.
- Both range bounds, negative equity, missing payoff, and editable assumptions behave correctly.
- Net proceeds are calculated from both value bounds and presented as a range.
- Every seeded deduction has an approved value, source, jurisdiction, effective date, and editable label.
- No LLM generates authoritative numbers.
- Financial calculations live in one pure framework-free module with no UI or provider imports; UI and server tests use the same module.

## Integration

- Provider responses match the documented contract.
- Secrets are absent from browser bundles and history.
- One request creates one CRM contact/update.
- Repeated submissions are idempotent.
- The request token, HMAC fingerprint, 15-minute window, and duplicate receipt behavior match the documented contract.
- Failures are observable and recoverable.
- Consent and source attribution survive ingestion.

## Experience and safety

- Desktop/mobile match approved references.
- Keyboard and screen-reader smoke tests pass.
- Loading corresponds to real work.
- Sensitive fields and logs are minimized.
- Preview and production are separate.
- HomeTwin data is never queried.
- Private MLS fields, non-public loan or distress data, CRM history, and third-party behavioral profiles are never queried for the result.
- Tests confirm that a provider response containing an ineligible private field is filtered server-side and never reaches browser output, logs, analytics, reports, or CRM.

## Abuse, cost, and performance

- Per-session and per-IP limits are enforced server-side.
- Honeypot and server-verified bot challenge run before a paid lookup.
- Concurrent identical lookups coalesce.
- Cache behavior and TTL match the provider contract; caching is disabled when prohibited.
- Spend alerts fire at 50% and 80%, and paid lookups stop at the configured daily cap.
- The cap state provides the documented graceful alternative.
- Mobile LCP, initial transfer, cached latency, and uncached latency meet the Phase 1 budgets in a preview environment.
